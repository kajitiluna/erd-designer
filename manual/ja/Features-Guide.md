# 各機能について

この包括的なガイドでは、ERD Designer で利用可能なすべての機能について、TODO アプリケーションのデータベース構造を例にした詳細な説明を提供します。

## 3.1. テーブル

テーブルは、あらゆるエンティティ関係図の中核コンポーネントです。ERD Designer は包括的なテーブル管理機能を提供します。

### 3.1.1. テーブル作成概要

ERD Designer でのテーブル作成は簡単で、ガイド付きプロセスに従います。

#### 新しいテーブルの作成

1. **テーブルモードの選択**
   - 編集モードパネルで **TABLE** ボタンをクリックします
   - ボタンがハイライト表示され、テーブル作成モードがアクティブであることを示します

2. **テーブルの配置**
   - テーブルを配置したいキャンバス上の任意の場所をクリックします
   - テーブル作成ダイアログが自動的に開きます

   ![テーブル作成ダイアログ](../screenshots/table-creation-dialog.png)

3. **テーブルプロパティの設定**
   - **物理名**: データベース内の実際のテーブル名（例：「users」）
   - **論理名**: 人間が読みやすい説明（例：「Users」）
   - **説明**: テーブルのオプションの文書化

4. **カラムの追加**
   - 「カラム追加」ボタンを使用して新しいカラムを作成します
   - 各カラムには独自の設定ダイアログがあります

#### 例：Users テーブルの作成

TODO アプリケーション用の users テーブルを作成しましょう：

```
物理名: users
論理名: Users
説明: TODO アイテムを作成・管理できるアプリケーションユーザー
```

### 3.1.2. カラム追加、編集、削除

カラムは、テーブルの構造とデータタイプを定義します。

#### カラムの追加

1. **カラム作成へのアクセス**
   - テーブル編集ダイアログで **「カラム追加」** をクリックします
   - カラム編集ダイアログが開きます

   ![カラム編集ダイアログ](../screenshots/column-edit-dialog.png)

2. **カラムプロパティの設定**
   - **物理名**: データベースカラム名（例：「id」）
   - **論理名**: 説明的な名前（例：「ユーザーID」）
   - **カラムタイプ**: データベース固有のタイプから選択
   - **制約**: 主キー、Not Null、Unique など

3. **主キーの設定**
   - 「主キー」をチェックしてテーブルの主キーにします
   - 自動的に「Not Null」制約が設定されます
   - 「Unique」は無効化されます（主キーとして自動的にユニーク）

4. **データタイプの選択**
   - データベース固有のタイプの豊富なリストから選択
   - PostgreSQL の場合：serial、integer、varchar、text、timestamp など
   - 数値タイプの精度とスケールオプション
   - PostgreSQL の配列サポート

#### 例：Users テーブルのカラム作成

**ID カラム（主キー）:**
```
物理名: id
論理名: ユーザーID
タイプ: SERIAL
制約: 主キー、Not Null
```

**ユーザー名カラム:**
```
物理名: username
論理名: ユーザー名
タイプ: VARCHAR(50)
制約: Not Null、Unique
```

**メールカラム:**
```
物理名: email
論理名: メールアドレス
タイプ: VARCHAR(255)
制約: Not Null、Unique
```

**作成日時カラム:**
```
物理名: created_at
論理名: 作成日時
タイプ: TIMESTAMP WITHOUT TIME ZONE
制約: Not Null
デフォルト値: CURRENT_TIMESTAMP
```

#### 既存カラムの編集

1. **カラムの選択**: テーブルエディターでカラム行をクリックします
2. **編集ボタン**: 「カラム編集」ボタンをクリックします
3. **プロパティの変更**: 必要に応じてカラムプロパティを更新します
4. **変更の保存**: 「OK」をクリックして変更を適用します

#### カラムの削除

1. **カラムの選択**: 削除したいカラムをクリックします
2. **削除ボタン**: 「カラム削除」ボタンをクリックします
3. **確認**: プロンプトで削除を確認します

### 3.1.3. インデクス追加、編集、削除

インデクスは、データベースクエリのパフォーマンスを向上させ、制約を強制します。

#### インデクスの作成

1. **インデクスタブへのアクセス**: テーブルエディターで「インデクス」タブをクリックします
2. **インデクス追加**: 「インデクス追加」ボタンをクリックします
3. **インデクスの設定**:
   - **インデクス名**: インデクスの説明的な名前
   - **インデクスタイプ**: BTREE、HASH、GIST など（データベース依存）
   - **カラム**: 含めるカラムを選択
   - **ユニーク**: ユニークインデクスにする場合はチェック

#### 例：Users テーブルのインデクス作成

**ユーザー名インデクス:**
```
名前: idx_users_username
タイプ: BTREE
カラム: username
ユニーク: はい
```

**メールインデクス:**
```
名前: idx_users_email
タイプ: BTREE
カラム: email
ユニーク: はい
```

### 3.1.4. ドラッグ移動、カラー変更、編集、削除

#### テーブルの移動

1. **選択モード**: SELECT モードになっていることを確認します
2. **クリック・アンド・ドラッグ**: テーブルをクリックしてドラッグして移動します
3. **細かい位置調整**: 矢印キーを使用して正確な位置調整を行います

#### テーブルの色変更

1. **テーブルの右クリック**: コンテキストメニューにアクセスします
2. **色の選択**: 事前定義された色またはカスタム色から選択します
3. **適用**: テーブルの背景が即座に更新されます

#### テーブルの編集

1. **ダブルクリック**: 任意のテーブルをダブルクリックして編集ダイアログを開きます
2. **プロパティの変更**: テーブル名、説明、カラム、インデクスを更新します
3. **変更の保存**: 「OK」をクリックしてすべての変更を適用します

#### テーブルの削除

1. **テーブルの選択**: テーブルをクリックして選択します
2. **Delete キー**: Delete キーを押すか
3. **コンテキストメニュー**: 右クリックして「削除」を選択します
4. **確認**: 削除を確認します（関連するすべての関係も削除されます）

## 3.2. リレーション

リレーションは、データベース内のテーブル間の接続と依存関係を定義します。

### 3.2.1. リレーション作成方法

#### リレーションシップの作成

1. **リレーションモードの選択**
   - 編集モードパネルで **RELATION** ボタンをクリックします

2. **ソーステーブルの選択**
   - リレーションシップのソースとなるテーブルをクリックします
   - これは通常、主キーを含むテーブルです

3. **ターゲットテーブルの選択**
   - ターゲットテーブルをクリックしてリレーションシップを完成させます
   - リレーション編集ダイアログが開きます

   ![リレーション編集ダイアログ](../screenshots/relation-edit-dialog.png)

#### 例：TODO アプリのリレーション作成

**Users から TODO Items へのリレーションシップ:**
```
ソーステーブル: users (id)
ターゲットテーブル: todo_items (user_id)
リレーションシップタイプ: 一対多
外部キー: user_id references users(id)
```

### 3.2.2. リレーション設定内容

#### リレーションシップ設定オプション

1. **カーディナリティ**:
   - **一対一**: テーブル A の各レコードがテーブル B の一つのレコードに関連
   - **一対多**: テーブル A の各レコードがテーブル B の複数のレコードに関連可能
   - **多対多**: 両方のテーブルのレコードが複数のリレーションシップを持つ可能

2. **外部キー設定**:
   - **カラムマッピング**: リレーションシップに参加するカラムを定義
   - **削除時アクション**: CASCADE、RESTRICT、SET NULL、SET DEFAULT
   - **更新時アクション**: CASCADE、RESTRICT、SET NULL、SET DEFAULT

3. **命名規則**:
   - **リレーションシップ名**: リレーションシップの論理名
   - **外部キー名**: データベース内の物理制約名

### 3.2.3. リレーション線の変更

#### 視覚的カスタマイゼーション

1. **線のスタイル**: 異なるリレーションシップタイプに対する異なるスタイル
2. **カラス足記法**: カーディナリティの視覚的インジケーター
3. **接続ポイント**: リレーションは特定のカラムに接続
4. **ルーティング**: ERD Designer は重複を避けるために自動的に線をルーティング

#### 既存リレーションの編集

1. **ダブルクリック**: 任意のリレーション線をダブルクリックします
2. **設定の変更**: カーディナリティ、制約、命名を更新します
3. **視覚的調整**: 中間ポイントをドラッグして線のルーティングを調整します

## 3.3. メモ

メモは ERD 内で文書化とノートを提供します。

### 3.3.1. メモ作成概要

#### メモの作成

1. **メモモードの選択**: **MEMO** ボタンをクリックします
2. **メモの配置**: メモを置きたいキャンバス上をクリックします
3. **テキストの入力**: 文書化やノートを入力します
4. **フォーマット**: 必要に応じて外観をカスタマイズします

### 3.3.2. テキスト編集方法

#### メモコンテンツの編集

1. **ダブルクリック**: 任意のメモをダブルクリックしてテキストを編集します
2. **リッチテキスト**: 基本的なフォーマットオプションをサポート
3. **複数行**: 改行を含む詳細な文書化を作成します

### 3.3.3. サイズ変更、位置移動、カラー変更、フォント変更、削除

#### メモのカスタマイゼーション

1. **リサイズ**: コーナーハンドルをドラッグしてメモボックスのサイズを変更
2. **移動**: クリック・アンド・ドラッグでメモを再配置
3. **色**: 右クリックして色オプションにアクセス
4. **フォント**: フォントファミリー、サイズ、スタイルを変更
5. **削除**: 選択して Delete キーを押す

## 3.4. その他の編集機能

### 3.4.1. カラムグループ定義

カラムグループを使用すると、関連するカラムを整理し、テーブル間で共通のパターンを再利用できます。

#### カラムグループの作成

1. **グループへのアクセス**: 「グループカラム追加」機能を使用します
2. **パターンの定義**: 再利用可能なカラムセットを作成します
3. **グループの適用**: 事前定義されたカラムグループをテーブルに追加します

#### 例：共通カラムグループ

**監査カラムグループ:**
```
created_at: TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
updated_at: TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
created_by: INTEGER REFERENCES users(id)
updated_by: INTEGER REFERENCES users(id)
```

### 3.4.2. DDL インポート

既存のデータベース構造を SQL DDL スクリプトからインポートします。

#### DDL のインポート

1. **インポートへのアクセス**: メニューから DDL インポート機能を使用します
2. **DDL の貼り付け**: SQL CREATE TABLE ステートメントを貼り付けます
3. **構造の解析**: ERD Designer が分析してテーブルを作成します
4. **結果の確認**: インポートされた構造を確認し、調整を行います

## 3.5. その他の操作

### 3.5.1. 単一選択、複数選択、Grab操作

#### 選択操作

1. **単一選択**: 任意の要素をクリックして選択します
2. **複数選択**: 
   - Ctrl/Cmd を押しながら複数の要素をクリック
   - ドラッグして選択矩形を作成
3. **すべて選択**: Ctrl+A を使用してすべての要素を選択

#### Grab 操作

1. **Grab モードの起動**: GRAB ボタンをクリックします
2. **キャンバスのパン**: クリック・アンド・ドラッグして全体の表示を移動
3. **ズームナビゲーション**: 大きな図をナビゲートするのに便利

### 3.5.2. デフォルトカラー設定

#### 色管理

1. **設定へのアクセス**: 設定ボタンをクリックします
2. **デフォルト色**: 新しいテーブルのデフォルト色を設定
3. **色テーマ**: 一貫した色スキームを適用
4. **カスタム色**: カスタムカラーパレットを定義

### 3.5.3. Display Style

#### 表示オプション

1. **物理名**: データベースカラム名のみを表示
2. **論理名**: 説明的な名前のみを表示
3. **両方**: 物理名と論理名の両方を表示（デフォルト）

#### 使用シナリオ

- **開発**: 技術的正確性のために物理名を使用
- **文書化**: ビジネス関係者のために論理名を使用
- **両方**: 設計とレビューのための包括的な表示

### 3.5.4. アンドゥ、リドゥ

#### 履歴管理

1. **アンドゥ**: Ctrl+Z またはアンドゥボタンをクリック
2. **リドゥ**: Ctrl+Y またはリドゥボタンをクリック
3. **履歴の深さ**: 複数レベルのアンドゥ/リドゥが利用可能
4. **視覚的インジケーター**: 利用可能なアクションがない場合はボタンが無効化

### 3.5.5. DDL エクスポート

#### SQL スクリプトの生成

1. **エクスポートへのアクセス**: エクスポート → 「DDL エクスポート」をクリック
2. **データベースターゲット**: ターゲットデータベースシステムを選択
3. **オプション**: エクスポート設定を構成
4. **生成**: SQL CREATE TABLE ステートメントを作成

#### DDL 出力例

```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50) NOT NULL UNIQUE,
    email VARCHAR(255) NOT NULL UNIQUE,
    created_at TIMESTAMP WITHOUT TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE todo_items (
    id SERIAL PRIMARY KEY,
    user_id INTEGER NOT NULL REFERENCES users(id),
    title VARCHAR(200) NOT NULL,
    description TEXT,
    completed BOOLEAN NOT NULL DEFAULT false,
    created_at TIMESTAMP WITHOUT TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

### 3.5.6. ER図 画像保存

#### 画像のエクスポート

1. **エクスポートへのアクセス**: エクスポート → 「画像として保存」をクリック
2. **画像形式**: 透明背景の PNG 形式
3. **品質**: 文書化に適した高解像度出力
4. **ダウンロード**: 画像が自動的にデバイスにダウンロード

![ERD 出力例](../screenshots/example-erd-output.png)

### 3.5.7. テーブル定義書出力

#### 仕様書

1. **エクスポートへのアクセス**: エクスポート → 「仕様書エクスポート」をクリック
2. **形式**: 
   - オンライン版では Excel ファイル（.xlsx）
   - Google Drive App では Google スプレッドシート
3. **内容**: すべてのメタデータを含む包括的なテーブル定義

#### 文書の内容

- テーブル名と説明
- データタイプを含むカラム定義
- 主キーと外部キーのリレーションシップ
- インデクス定義
- 制約とデフォルト値

### 3.5.8. erd ファイル出力（Google Drive App 除く）

#### ネイティブファイル形式

1. **エクスポートへのアクセス**: エクスポート → 「ERD ファイルに保存」をクリック
2. **ファイル形式**: 完全な図データを含む .erd ファイル
3. **可搬性**: ファイルは他のユーザーと共有してインポート可能
4. **バージョン管理**: 時間の経過とともに変更を追跡するのに適しています

#### ファイルの使用

- **バックアップ**: 作業のバックアップを作成
- **共有**: チームメンバーと図を共有
- **バージョン管理**: Git やその他のシステムを使用して変更を追跡
- **移行**: オンラインとローカルインストール間で図を移動
